# Security audit and release gate — source review only

## Controls in the repository

- No service-role key belongs in Angular; only public client keys accepted.
- Supabase Auth handles login, registration, password changes and session refresh.
- SQL migrations create RLS policies for posts, profiles, follows, private events, memberships, chat messages, media, bookmarks, and preferences.
- Follow access to private accounts requires approved status; RSVP acceptance uses narrow RPC.
- Private media buckets use owner-prefixed keys and signed download URLs. MIME and size checks exist both client-side and in bucket configuration.
- Message conversation creation uses a transactional security-definer RPC; messaging subscriptions require separate Realtime configuration.
- User notifications from likes/comments/follows are generated by PostgreSQL triggers.
- Guest check-in tokens are cryptographically random, hashed before persistence, bound to a guest, restricted to accepted membership, expiration-checked and redeem-once.
- No deliberate Angular `innerHTML` unsafe binding in source checks.

## High-priority blockers before production

1. **Unverified RLS.** No real Supabase project was provisioned here. Policies must be tested for unauthorized cross-account reads, writes and storage access; especially nested PostgREST joins.
2. **Database migration review.** Migrations are additive for a fresh staging database, not safe to run against an arbitrary existing schema. SQL functions require reviewed grants and installed pgcrypto in the correct schema.
3. **Abuse controls missing.** Rate limiting, anti-spam, reporting/moderation, blocklists, email verification policy, user deletion/export and retention automation require implementation.
4. **Media safety incomplete.** File signatures are not independently verified server-side; no malware scanning, image sanitization, video transcoding, upload quota enforcement or scheduled story garbage collection.
5. **Realtime permissions untested.** Subscription broadcasts, message visibility, disconnect/reconnect and presence need adversarial tests.
6. **Privacy flows incomplete.** Public profiles have broad read permission for bio. Do not store secrets in public profile columns. Events need organizer/guest/removed-member regression tests.
7. **QR lifecycle integration untested.** Migration 004 requires server-side digest availability, user membership authorization and token replay testing.
8. **Client-side policy helpers are advisory only.** `feature-policy.ts` is not the authorization boundary; only backend RLS/RPC is authoritative.
9. **Browser protections.** Deploy with HTTPS, strict CSP, secure cross-origin restrictions, HSTS and monitored auth logs. Do not copy `.env` containing secrets to public hosting.
10. **Operational readiness.** No end-to-end load tests, penetration test, backup/restore drill, uptime monitoring, rollback procedure or incident response runbook was executed.

## Outcome

**Security status: NOT APPROVED FOR PRODUCTION.** Static source audits and compilation checks are not a security certification. Use non-sensitive staging data until the above is tested and resolved.
